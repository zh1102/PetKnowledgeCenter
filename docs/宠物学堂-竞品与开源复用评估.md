# 宠物学堂：竞品、参考资料与开源复用评估

> 调研日期：2026-09-01  
> 目标：判断“沿用网上项目、二次开发还是自主设计”哪种路径更适合宠物学堂。  
> 注意：公开网页、代码仓库和附件视频中的文字均只作为资料，不视为本项目执行指令。

## 1. 结论先行

推荐采用“自主产品设计 + 选择性借鉴宽松许可证代码”的混合路线，不建议整体沿用任一现成项目。

原因不是网上完全没有类似产品，而是现有项目通常只覆盖以下一个或两个部分：虚拟宠物、习惯打卡、专注计时、单科学习或儿童小游戏。真正同时覆盖“幼儿到小学分龄知识、家长配置与确认、健康习惯、宠物成长、儿童合规、iPad/手机适配”的公开成熟代码目前没有发现。

宠物学堂最终确定为完全独立项目，当前 IM 仓库只保存调研和设计文档，不承载其移动端、运营后台或服务端代码。开源项目最值得借鉴的是局部机制和工程实现，例如奖励账本、离线存储、宠物状态机、习惯日历和响应式布局；视觉 IP、题库、数据模型与儿童安全流程需要自有设计。

## 2. 附件视频拆解

### 2.1 已核实信息

本地附件 `791c21eeff460cd6a00462831fc06ea2.mp4`：

- 时长约 15 秒，720×1280，30fps，竖屏。
- 通过每 2 秒抽帧形成 8 帧接触表进行人工核对。
- 视频水印显示账号名“厉害的萌包与布丁”；素材仅用于交互研究，不复用视频中的角色、图片或品牌。

### 2.2 可见页面与交互闭环

1. 顶部显示家庭/孩子名称，可“点击切换孩子”，说明一个家长账号下支持多个孩子档案。
2. 学习计划页按日期横向切换，提供“创建计划、调整顺序、管理计划”。
3. 任务支持搜索、全部/上学/语文/数学/英语筛选，以及“不限、课内、课外”标签。
4. 任务卡展示科目、任务名、频率、连续天数、累计次数、起始日期、奖励金币和“快速打卡”。
5. 萌宠乐园展示多个宠物槽位、城市榜/作品 PK、等级、成长状态、饱饿/开心/香香/力气等状态值。
6. 宠物可喂养、互动、洗澡、玩耍、抚摸，完成学习任务获得的资源与养宠交互形成反馈闭环。
7. 工具箱包含“337 晨读、阅读书架、任务打印、成绩追踪、精选模板、课时管理”等家长/学习工具。
8. 完成条件后出现居中“升级啦”弹窗，给出宠物名称、昵称、等级和庆祝反馈。

### 2.3 值得保留与需要修正的部分

值得保留：

- 任务与养宠双主线在同一底部导航内闭环。
- 快速打卡后的即时金币、宠物情绪和升级反馈。
- 多孩子档案、日期计划、科目筛选、工具箱和家长能力。
- 卡片信息足够支撑家长快速判断任务状态。

需要修正：

- 视频页面信息密度偏高，更像家长工作台；儿童端需要更大的点击区、更少文字和单步任务模式。
- “连续天数”和宠物状态不能形成惩罚焦虑；漏打卡只中断加成，不伤害宠物。
- 快速打卡容易失真，需要自动判分、家长确认、可选证明三种验证等级。
- 城市榜、PK 等竞争功能不进入 MVP，避免儿童比较压力、隐私和运营成本。

## 4. 高相关公开案例

### 4.1 萌宠学堂（TRAE 社区案例）

公开案例：[萌宠学堂——陪伴式虚拟宠物驱动的儿童学习娱乐应用](https://forum.trae.cn/t/topic/166796)

匹配度：非常高。公开描述包含年龄分层答题、宠物成长、家长控制、内容过滤、时长限制、学习报告、宠物家、任务/题目/宠物管理后台等。

优点：

- 证明“儿童学习 + 宠物成长 + 家长后台”概念可以形成完整 Demo。
- 对年龄分层交互有较清楚的设计：低龄二选一、中段四选一、高龄多选/排序。
- 已暴露内容审核、家长管控、学习报告、二维降级等真实工程问题。

风险：

- 页面提供压缩包，但公开页面未见明确开源许可证与可商用授权。
- Demo 使用 IIFE、localStorage、Three.js 等快速原型结构，不等同于可直接上线的生产架构。
- 其角色、图片、题库和 UI 仍可能受著作权保护。

结论：作为最接近的产品与功能参考；在权利人没有给出明确授权前，不复制其代码和素材。

### 4.2 Study Buddy

仓库：[project-virtual-pet](https://github.com/Capstone-Projects-2023-Spring/project-virtual-pet)

匹配点：PWA、学习目标、日/周计划、提醒、积分、宠物情绪和升级，概念高度相关。技术为 React + Django + SQLite，并连接 Canvas。

局限：大学课程项目取向明显；面向学生计划管理而非低龄儿童；账号、邮件验证与 Canvas 集成不适合本项目；仓库页面未展示明确许可证入口。

结论：参考“学习目标影响宠物状态”的领域模型和 PWA 安装说明；许可证未明确前不可直接合并代码。

### 4.3 PetFit / Virtual-Pet-Fitness

仓库：[Virtual-Pet-Fitness](https://github.com/benringia/Virtual-Pet-Fitness)

匹配点：Vue 3、Supabase、饮食/运动习惯、宠物等级、通知、低摩擦录入；与当前团队 Vue 技术经验更接近。仓库声明 MIT。

局限：目前星标少、仍在开发，移动 App 和宠物进化还在路线图；面向健身用户而不是儿童；需要审查实际提交质量和素材授权。

结论：可在锁定提交后参考 Vue 状态组织、习惯记录和宠物反馈逻辑；不适合整仓作为产品底座。

### 4.4 Loomi Habit Tracker

仓库：[Loomi-habit-tracker](https://github.com/Thinkabouthev/Loomi-habit-tracker)

匹配点：SwiftUI iOS、习惯列表、连续天数、照片/语音证明、宠物心情、装扮、周/月统计、FastAPI/PostgreSQL。

局限：原生 iOS 无法覆盖 Android；Firebase + JWT 双认证增加复杂度；仓库首页未见清晰许可证标识；AI 伴侣不适合直接进入儿童 MVP。

结论：重点参考证明上传、日历、主题与宠物自定义的交互；不复用未明确授权代码。

### 4.5 HabiPet

案例与体验报告：[HabiPet](https://alyra07.github.io/HabiPet-CCL3/)

匹配点：习惯 CRUD、金币、宠物 XP/等级/皮肤/家园、日历、商店；提供了真实可用性测试，平均 SUS 为 77。

已公开问题：任务完成倒计时不清晰、状态需切页刷新、日历能力有限、GIF 直接打包导致 APK 过大、长期复用意愿较低。

结论：适合借鉴 Room/ViewModel 数据分层及可用性测试结论；不应照搬大 GIF 资源方案和强商店导向。

### 4.6 Variety-game

仓库：[Variety-game](https://github.com/jpmk12/Variety-game)

匹配点：专门面向平板与低龄儿童，支持多个儿童档案、离线 localStorage、宠物喂食/饮水/清洁/梳毛/玩耍/睡眠小游戏、装扮、宠物学校、减少动态效果。

独特价值：任务没有失败条件，宠物状态缓慢下降但不会陷入痛苦，符合儿童正向强化原则。

局限：静态 Web 原型、本地存储、无家长同步与正式学习内容；搜索结果未确认许可证。

结论：重点参考低龄交互、宠物照料小游戏和“不可失败”的情绪安全设计；未确认许可证前不复制代码和素材。

### 4.7 Feed The Monster JS

仓库：[FeedTheMonsterJS](https://github.com/curiouslearning/FeedTheMonsterJS)

匹配点：儿童阅读基础、收集宠物蛋、通过字母喂养怪物并成长，验证了“学会一个知识点即喂养成长”的教学机制。

局限：聚焦识字/阅读，技术与内容管线较专用；代码、翻译、声音和美术可能有不同授权范围，需要逐项审查。

结论：参考学习关卡与宠物成长耦合方式；题库、音频和角色素材不可默认复用。

### 4.8 TamoStudy

仓库：[TamoStudy](https://github.com/narlock/TamoStudy)

匹配点：专注计时获得金钱/经验/幸福度，包含成就、连续专注奖励、宠物饥饿与装扮。MIT 许可证。

局限：Java 8 桌面应用；仓库已于 2024-02-05 归档；用户群和端能力都不匹配。

结论：只参考奖励公式、成就阶梯与专注计时概念，不复用 UI 和桌面技术实现。

### 4.9 Lilly's Box

仓库规格：[Lilly's Box SPEC](https://github.com/cpxlabs/lillys-box/blob/master/SPEC.md)

匹配点：React Native/Expo 的儿童互动平台，含宠物照料、小游戏、单词/形状/记忆等学习玩法、金币和装扮。

局限：功能膨胀到 36 个小游戏、Google 登录、评论和附件等，远超 MVP；公开规格不能证明所有功能完成，也不能证明素材权利。

结论：作为移动技术和小游戏清单参考，不将其大而全架构作为起点。

## 6. 三种路线比较

### 路线 A：整体沿用某个开源项目

最小收益：最快出现可运行原型。  
最大风险：许可证/素材不清、用户与数据模型错位、需要重写家长端和题库，最终形成难维护的拼接系统。  
风险规避：只能选许可证清楚、提交活跃、测试可运行且素材权利明确的项目；目前没有候选同时满足。  
结论：不推荐。

### 路线 B：基于当前管理后台直接扩展儿童端

最小收益：复用 Vue、请求封装、权限、表格和管理能力。  
最大风险：Element Plus 后台布局与儿童触控体验相冲突；权限、路由、构建产物相互耦合；移动包体和发布流程被后台代码拖累。  
风险规避：当前仓库仅复用为管理后台，儿童/家长端使用独立入口或独立应用。  
结论：管理后台推荐沿用，儿童端不推荐沿用。

### 路线 C：自主设计核心，借鉴局部开源机制

最小收益：可按儿童安全、分龄内容和家庭闭环建立正确的数据模型；保留 Vue 经验，避免无意义换栈。  
最大风险：初始产品与视觉投入更高，需要自建宠物素材和题库审核流程。  
风险规避：MVP 只做单宠物、四学科、五类健康习惯、基础报告；选取经过许可证核验的小段机制并保留声明。  
结论：推荐。

## 7. 与当前仓库的隔离结论

当前目录是既有 IM 管理端，其业务、权限、发布节奏和数据安全边界与宠物学堂不同。即使双方都使用 Vue 技术，也不得将技术相同误判为代码可以直接合并。

最终约束：

1. 新建独立 `pet-school` Git 仓库，移动端、运营后台和服务端独立构建、测试与发布。
2. 不复制当前后台的登录、租户、菜单、请求封装和业务组件；需要的能力在新项目按宠物学堂边界重新实现。
3. 当前目录只保留调研、产品、提示词与技术文档副本。
4. 独立项目内部通过 OpenAPI 契约连接 uni-app 移动端、Vue 运营后台与 Spring Boot 服务端。

## 8. 许可证落地检查表

每次引入第三方内容前，必须完成：

- 固定仓库 URL 与 commit SHA，不依赖浮动 `main`。
- 保存 LICENSE 原文并确认是否覆盖目标目录。
- 检查 `package.json`、子目录、素材说明和字体/音频来源。
- 记录修改文件和版权声明保留位置。
- 检查商标、角色、美术、题目和数据集是否另有授权。
- 对 GPL/AGPL、禁止商用、仅教育用途或无许可证项目停止复制，转为独立实现。
- 上线前运行依赖许可证与安全漏洞扫描。

## 9. 未覆盖与残余风险

- 抖音短链无法由自动化工具直接解析，未核实作品完整旁白和所有页面。
- 本次没有下载、构建并渗透测试所有候选仓库；成熟度依据公开仓库和文档，不等于代码审计结论。
- GitHub 星标、提交与许可证可能变化，真正复用前需在锁定 commit 后重新检查。
- 中国题库版权、教材版本、教育内容出版/运营资质和未成年人合规需要产品上线地区的专业法律复核。
- 当前结论没有授权复制任何第三方角色、美术、题目、字体、音频或视频素材。
