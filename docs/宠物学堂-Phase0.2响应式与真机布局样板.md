# 宠物学堂 Phase 0.2 响应式与真机布局样板

> 执行日期：2026-09-28
> 基线提交：`37f9dd035a9aec36eebd17ea40f0df70cc64863d`
> 范围：现有领养页、今日任务页、首页与宠物页面壳层；不增加业务页面或服务端能力。
> 状态：响应式样板和 App 资源构建已完成，iOS/Android 实体设备安装验收待执行。

## 1. 本阶段验收标准

| 编号 | 标准 | 判定方式 |
|---|---|---|
| R-01 | 覆盖 360×640、640×360、390×844、844×390、768×1024、1024×768、820×1180、1180×820、1024×1366、1366×1024 | Edge 设备仿真锁定精确 CSS 视口并截图 |
| R-02 | 手机横竖屏使用 64px 固定图标轨；iPad 保留 176px 文字导航；大横屏沿用现有 255px 视觉母版 | 截图检查导航宽度、标签和选中态 |
| R-03 | 页面不得产生横向滚动，文字、卡片和按钮不得越过视口 | 比较 `documentElement.clientWidth` 与页面 `scrollWidth` |
| R-04 | 可见按钮最小高度 44px | 浏览器读取每个可见按钮的边界矩形 |
| R-05 | 手机横屏首屏不得被竖屏大标题占满，核心任务或领养卡可见 | 640×360、844×390 截图检查 |
| R-06 | 移动浏览器工具栏、软键盘和圆角屏使用动态视口、安全区及可滚动弹窗兜底 | 代码检查 `100dvh`、`env(safe-area-inset-*)`、弹窗 `max-height` 与滚动 |
| R-07 | 系统减少动态效果时不依赖动画完成业务操作 | 保留并检查既有 `prefers-reduced-motion` 静态回退 |
| R-08 | H5 与 App 资源构建通过，现有领域规则不回归 | `npm run check`、`npm run build:app` |

## 2. 实施内容

1. 页面壳层增加 `100dvh`，保留 `100vh` 兼容回退；全局阻止非预期横向滚动。
2. 全局按钮热区下限统一为 44px，不缩小现有主按钮。
3. 手机侧栏从 72px 修正为规格要求的 64px；手机横屏断点同样切换为图标轨。
4. 手机横屏压缩首页、今日任务和宠物页面的头部与主插画高度，保留正文完整换行。
5. 页面右侧、侧栏左侧、弹窗底部接入安全区内边距。
6. 今日任务与宠物弹窗改用动态视口高度，软键盘或地址栏改变可用高度时仍可滚动。

## 3. 自动化视口结果

领养页与今日任务页各执行 10 个视口，共 20 个用例：

- 20/20 的浏览器报告宽度等于目标 CSS 视口。
- 20/20 的 `scrollWidth` 等于 `clientWidth`，没有横向页面滚动。
- 20/20 未发现可见按钮高度低于 44px。
- 手机横屏 640×360、844×390 均使用 64px 图标侧栏。
- 领养页在窄屏使用单列；今日任务页在 iPad 横屏使用双栏，在手机横竖屏使用稳定单列。

证据目录：`资产/UI/app-responsive-v1/验收/`。

- `responsive-results.json`：20 个视口的宽高、滚动范围、热区检查结果。
- `adoption-*.png`：10 个领养页精确视口截图。
- `today-*.png`：完成 Mock 领养后的 10 个今日任务页精确视口截图。

## 4. 边界与对抗性检查

### 恶意或异常输入

- 超长宠物名继续使用现有 `overflow-wrap:anywhere` 和按钮弹性换行，未修改业务校验上限。
- 页面内容超出一屏时允许纵向滚动；不通过缩小字体或裁剪内容伪造“一屏显示”。
- 弹窗内容过长或软键盘出现时限制在动态视口内并允许内部滚动。

### 挑剔评审

- 手机导航严格按 64px 规格执行，未擅自改为底部导航。
- 所有状态仍使用文字、图标或数值共同表达，不只依赖颜色。
- 本阶段没有添加新依赖、路由、业务状态或接口。

### 极端环境

- 360px 最窄视口保留 296px 正文宽度，未出现横向滚动。
- 360px 高横屏允许纵向滚动，首屏可看到标题和主要卡片。
- `prefers-reduced-motion` 保持静态回退；动画资源加载失败仍沿用既有静态图逻辑。
