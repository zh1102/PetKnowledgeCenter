# 宠物学堂独立技术设计文档

> 版本：v1.1  
> 日期：2026-09-03  
> 状态：技术基线已确定，尚未创建代码工程  
> 边界：宠物学堂是全新独立产品，不继承当前目录中 IM 管理端的 Vue、RuoYi、权限、接口或部署体系。

## 1. 技术目标

技术方案必须支撑以下产品闭环：

> 审核内容每日下发 → 儿童离线或在线完成学习/习惯任务 → 自动判分或家长确认 → 服务端幂等奖励 → 宠物状态与成长 → 家长报告反向调整计划。

首版成功标准：

- 一套移动代码稳定支持 iPad、iPhone 和 Android 手机。
- 描红、数独、舒尔特方格和轻量宠物互动在中低端设备上保持可用。
- 断网、中断、跨日和重复点击不会丢失作答或重复发奖。
- 儿童数据按家庭和孩子双重隔离，证明文件不可通过公开 URL 枚举。
- 题目、音频、插画和实验内容有版本、审核及下架能力。
- 单体部署即可完成 MVP，不以微服务、Kubernetes 或消息队列作为前置条件。

## 2. 技术选型结论

| 层级 | 选型 | 结论 |
|---|---|---|
| 儿童/家长移动端 | uni-app + Vue 3 + TypeScript | 默认方案，只发布 App-iOS/App-Android |
| 状态管理 | Pinia | 按功能模块组织状态，不建立全局巨型 Store |
| 页面与导航 | uni-app 页面路由 | 页面白名单、家长区守卫和明确返回栈 |
| 本地数据库 | SQLite | 题目包、草稿、同步队列和只读历史缓存 |
| 网络 | `uni.request` 封装 | 超时、刷新令牌、幂等键和错误映射 |
| 绘制 | Canvas + renderjs | 田字格、笔迹、数轴、十格框、舒尔特方格 |
| 宠物动画 | WebP 序列帧/CSS，Lottie 备选 | 先验证轻量方案；动画失败时静态图兜底 |
| 服务端 | Java 21 + Spring Boot 3.5.x | 模块化单体，保留将来拆分边界 |
| 数据访问 | MyBatis +显式 SQL | 可审计查询，禁止 `SELECT *` 和字符串拼接 |
| 数据库 | PostgreSQL 16+ | 主数据、奖励账本、JSON 内容配置和事务事实源 |
| 缓存/限流 | Redis 7，可延后启用 | MVP 单实例可先不用；多实例或验证码上线时启用 |
| 对象存储 | S3 兼容存储 | 音频、插画、动画包和可选证明材料 |
| 运营后台 | Vue 3 + TypeScript + Vite + Element Plus | 全新内容审核与运营应用，不复制当前后台代码 |
| 数据库迁移 | Flyway | 所有结构变更进入版本化脚本 |
| API 文档 | OpenAPI 3 | 生成移动端和后台的契约客户端或类型 |
| 部署 | Docker Compose 起步 | Nginx/API/PostgreSQL/可选 Redis/对象存储配置 |

版本规则：文档只锁定大版本和稳定分支；创建工程时记录具体版本与 lockfile，不使用 alpha、beta、RC 作为生产基线。

## 3. 选型比较与依据

### 3.1 移动端比较

| 方案 | 跨端一致性 | 自定义绘制/动画 | 原生能力 | 团队成本 | 本项目结论 |
|---|---:|---:|---:|---:|---|
| SwiftUI + Kotlin Compose | 高，但需双实现 | 最高 | 最高 | 最高 | 仅在双端团队充足时采用 |
| Flutter | 高 | 高 | 可通过插件/平台通道补齐 | 对现有人员高 | 技术能力强，但学习和维护成本高 |
| React Native | 中高 | 需依赖 Skia/Rive 等生态 | Native Module 成熟 | 中高 | 不具备现成 React Native 优势 |
| uni-app | 中高（仅 App 双端） | Canvas 高频交互需专项处理 | 插件可补齐 | 低 | 推荐，符合人员技能和 MVP 范围 |
| uni-app x | 中高 | 潜力高 | UTS 可访问原生能力 | 中 | 演进较快，首版生产风险更高 |

Flutter 官方列出 Android 与 iOS 为支持平台，绘制与动画能力较强：[Flutter 支持平台](https://docs.flutter.dev/reference/supported-platforms)。但当前实施者更熟悉 uni-app/Vue，强行换栈会把风险从局部 Canvas 优化转化为全项目学习、调试和发布风险。

React Native 可以用 Native Module/Component 接入 Swift、Kotlin 或 C++，但本项目仍需额外选择和维护绘制、动画生态：[React Native Native Platform](https://reactnative.dev/docs/native-platform)。

uni-app 官方说明 app-vue 的高频 Canvas 交互可以通过 `renderjs` 降低逻辑层与视图层通信损耗：[uni-app Canvas](https://uniapp.dcloud.net.cn/component/canvas)、[renderjs](https://uniapp.dcloud.net.cn/tutorial/renderjs)。本产品绝大部分是学习卡片、音频、表单、日历和轻互动，只有描红属于高频画布，因此选择熟悉的 uni-app，并把描红隔离为专项组件，比全量换成 Flutter 更符合最小风险原则。

选型限制：正式目标仅为 App-iOS 与 App-Android，不承诺同一套界面同时适配 H5、微信小程序或其他小程序。若以后增加小程序，必须重新评估 Canvas、录音、动画和离线能力，不得用条件编译不断堆积分支。

### 3.2 服务端比较

| 方案 | 业务事务 | 开发效率 | 性能/资源 | 生态与审计 | 本项目结论 |
|---|---:|---:|---:|---:|---|
| Java + Spring Boot | 高 | 高 | 中 | 高 | 推荐 |
| Go + Gin | 中高 | 中 | 高 | 中 | 小团队熟悉 Go 时可选 |
| Node.js + NestJS | 中 | 高 | 中 | 中 | 实时/前端同栈有利，但奖励事务优势不足 |
| Python + FastAPI | 中 | 高 | 中 | 中 | AI 适配服务合适，不作为核心事实源 |

推荐 Java 并不是因为当前目录像 RuoYi，而是奖励账本、任务实例、监护关系、审核发布和删除审计都属于事务密集型业务。Spring Boot 提供独立生产应用、校验、缓存、调度和可观测能力；当前官方仍维护 3.5 稳定分支：[Spring Boot 文档](https://docs.spring.io/spring-boot/)。

采用 Spring Boot 3.5.x 而不是 4.x，是为了首版获得更宽的三方库兼容区间；创建工程时选择当时最新的 3.5.x 补丁。Java 固定为 21 LTS，不在首版启用虚拟线程，避免连接池与线程模型未经压测就复杂化。

## 4. 总体架构

```text
uni-app 家庭应用                Vue 运营后台
  儿童模式 / 家长区                   内容/审核/运营
          │ HTTPS + JSON                     │
          └──────────────┬───────────────────┘
                         ▼
               Spring Boot 模块化单体
     ┌────────┬────────┬────────┬────────┬────────┐
     │身份家庭│内容发布│任务学习│奖励宠物│报告审计│
     └────────┴────────┴────────┴────────┴────────┘
           │             │              │
      PostgreSQL     S3 对象存储    外部语音评测适配器
           │
      Redis（按需启用）
```

### 4.1 为什么首版是模块化单体

- 所有核心写操作仍能使用单数据库本地事务。
- 部署、日志、监控、备份和故障定位成本低。
- 通过模块包边界和事件接口保留未来拆分能力。
- 当前没有独立团队、超大流量或隔离部署需求，微服务只会增加一致性问题。

禁止业务模块直接跨模块访问 Mapper；跨模块读取通过应用服务，跨模块副作用通过事务内领域事件处理。首版事件仍在进程内执行，需要可靠异步时再加入 outbox 和队列。

## 6. uni-app 移动端设计

### 6.1 功能目录

```text
src/
  pages/                    # 仅页面入口，不堆放业务规则
    onboarding/
    today/
    chinese/
    math/
    english/
    habits/
    science/
    pet/
    calendar/
    parent/
  features/                 # 按业务域组织组件、服务和模型
  components/               # 无业务状态的公共组件
  stores/                   # Pinia，按家庭/孩子/功能拆分
  services/
    api/                    # uni.request、令牌刷新、错误映射
    database/               # SQLite 与版本迁移
    sync/                   # 离线队列、冲突与重试
    audio/                  # 播放、录音、权限和中断
    drawing/                # Canvas、renderjs 与坐标归一化
    security/               # 安全存储、家长门
  static/                   # 首屏和兜底资源；大内容走资源包
  types/
  utils/
  pages.json
  manifest.json
```

复杂 `feature` 按 `components/services/models` 拆分；简单页面不建立空的领域分层。页面只能调用业务 service/store，不直接拼接 API、SQL 或奖励规则。

### 6.2 状态与导航

- Pinia Store 按孩子与功能拆分，切换孩子时取消旧请求并清理敏感内存状态。
- 页面不得直接读写 SQLite 或调用 `uni.request`；由业务 service 协调远端与本地数据。
- 家长区路由必须经过家长门状态；家长门只是防误触，敏感接口仍验证监护人令牌。
- 答题页离开前保存题目级草稿，不用全页序列化覆盖。
- 业务页面使用 Vue 3 Composition API；只有 `renderjs` 专项组件使用官方兼容的普通脚本写法，避免混用造成构建错误。

### 6.3 iPad 与手机布局

- iPad 横竖屏都使用固定约 176px 左侧导航。竖屏采用加宽单栏/局部双栏，横屏优先采用主从双栏，使用 CSS Grid/Flex 和可用宽度断点切换。
- 手机横竖屏都保留 64px 一级导航轨，二级入口位于内容顶部；竖屏使用单列，横屏在可用宽度允许时使用题干/操作紧凑双栏。
- 不直接按屏幕像素分支，基于可用宽度断点和 SafeArea。
- 横竖屏切换前保存答题、计时、音频、录音和描红状态；重新布局不能重新生成题目或重置计时。
- 支持字体放大、VoiceOver/TalkBack、减少动态效果和横竖屏中断恢复。

### 6.4 描红与自定义绘制

描红使用 app-vue Canvas，并把触摸采样与实时绘制放入 `renderjs`，避免每个触摸点跨层通信。笔迹坐标使用画布逻辑尺寸归一化保存，不能保存设备物理像素。一次描红包含：

- 字模版本、画布尺寸比例、笔画序号、点序列、开始/结束时间。
- 实时绘制在视图层完成；一笔结束后再将简化结果批量回传逻辑层，禁止逐点更新 Vue 响应式状态。
- 每完成一笔再持久化，不在每个触摸点写数据库。
- 首版只做笔顺引导与容差检测，不宣称书法质量评分。

异常覆盖：多指触摸、手掌误触、应用切后台、屏幕旋转、零长度笔迹、极快划线和撤销后重做。

### 6.5 音频、录音与语音评测

- 使用 `uni.createInnerAudioContext` 封装唯一的 AudioManager，不使用 Vue 3 已废弃的传统 `<audio>` 组件。
- 播放器必须支持播放、暂停、重播、慢速、耳机中断和后台恢复；慢速能力必须先在 iOS/Android 真机确认。
- 同一时间只允许一个教学音频源；切页时释放或按明确规则续播。
- 录音前由家长启用功能并展示用途；权限拒绝时仍可听读和人工打卡。
- 录音通过 uni-app 录音 API；原始文件先保存在应用私有目录，上传成功且校验完成后按策略删除本地临时文件。
- 语音评测采用 `SpeechAssessmentProvider` 接口隔离供应商；拼音与英语可使用不同实现。
- 供应商超时、低置信度或无法识别时返回“建议再听一次/请家长确认”，不能判孩子失败。

### 6.6 宠物动画

- 角色由状态机驱动：`idle/happy/hungry/cleaning/eating/playing/sleeping/studying/levelUp`。
- 业务状态不直接依赖动画帧；动画加载失败时显示静态兜底图和同等操作按钮。
- 首版优先使用 CSS 变换和 WebP/PNG 序列帧；只有技术样板证明包体、内存、暂停恢复均合格后才引入 Lottie 或原生动画插件。
- 动画文件、序列帧、音效和角色立绘均带 `assetId/version/license/hash`。
- 首发只完整制作猫；狗、兔等宠物先作为内容包能力预留，不预制未使用资源。
- 单页同时播放的持续动画数量设置上限，低性能设备与减少动态效果模式使用静态或低帧版本。

### 6.7 离线与同步

本地保存：已发布内容包、今日任务实例镜像、作答草稿、待同步操作、宠物只读快照和资源清单。

本地不作为事实源：星星余额、最终奖励、监护关系、内容审核状态和删除状态。

同步队列表字段：`operationId/type/entityId/payloadHash/baseVersion/createdAt/retryCount/nextRetryAt/status`。

规则：

1. 每个写操作生成 UUID 幂等键。
2. 网络恢复后按孩子和创建顺序发送。
3. 4xx 校验失败停止自动重试并提示可修复原因。
4. 401 先刷新令牌一次；失败则进入家长重新登录。
5. 429/5xx/超时指数退避并加随机抖动。
6. 服务端返回原始结算结果时，本地替换乐观状态，不累加第二次奖励。

## 7. 运营后台设计

独立 Vue 3 后台只覆盖宠物学堂，不复用当前 IM 后台：

- 账号、角色和最小权限
- 学段、教材版本、知识点
- 题目、短文、古诗、英语分级内容
- 音频、插画、动画、宠物与道具资源
- 居家实验风险分级
- 草稿、待审核、已发布、已下架工作流
- 发布批次、内容包和客户端最低版本
- 奖励规则与异常账本查询
- 儿童数据请求处理及审计

后台不能直接编辑儿童余额和已确认作答；修正必须生成可审计的调整记录。内容发布必须由不同权限的人员完成编辑和审核，MVP 人员不足时至少需要二次确认与完整日志。

## 8. Spring Boot 服务端设计

### 8.1 模块结构

```text
com.petschool
  bootstrap/               # 启动与装配
  common/                  # 受控的基础错误、时间、ID
  identity/                # 监护人登录、令牌、设备会话
  family/                  # 家庭、孩子档案、监护关系与同意
  content/                 # 知识点、内容、审核、发布包
  planning/                # 计划和每日任务实例
  learning/                # 作答、判分、错题与进度
  habit/                   # 家务、健康、兴趣和家长确认
  reward/                  # 星星账本、幂等和每日上限
  pet/                     # 宠物状态、成长、物品与互动
  calendar/                # 日历聚合与连续天数
  report/                  # 周报、月报和证据引用
  media/                   # 对象存储、临时凭证、删除
  speech/                  # 语音评测供应商适配
  audit/                   # 安全与敏感操作审计
  admin/                   # 运营后台用例入口
```

模块公开 `application` 接口和不可变 DTO，Mapper、数据库实体和内部领域对象不跨模块暴露。

### 8.2 REST 约定

成功响应：

```json
{
  "code": "OK",
  "msg": "success",
  "data": {}
}
```

失败使用正确 HTTP 状态码，并返回稳定业务码、用户可展示文案和 `traceId`。禁止把堆栈、SQL、手机号或对象存储真实路径返回客户端。

写接口公共头：

- `Authorization: Bearer <token>`
- `Idempotency-Key: <uuid>`
- `X-Child-Profile-Id: <id>`：只作为请求上下文，不能代替服务端监护关系校验。
- `If-Match: <version>`：用于计划、档案等可并发编辑资源。

| 媒体 | `POST /v1/media/upload-intents` | 获取受控上传凭证 |
| 隐私 | `POST /v1/privacy/export-requests` | 家长申请导出 |

接口路径不暴露数据库表名；列表全部分页并有稳定排序。

## 9. 数据库设计

### 9.1 通用规则

- 主键使用服务端生成的 UUIDv7/有序 UUID，客户端幂等键使用 UUIDv4。
- 时间存 `timestamptz` UTC；任务业务日期另存家庭时区下的 `local_date`。
- 业务表包含 `created_at/updated_at/version`；审计与账本表只追加。
- 软删除不能代替法定删除流程；冻结期结束后执行跨表和对象存储清理。
- JSONB 只用于版本化题目结构、展示配置和供应商原始结果，不用于可高频查询的核心关系。

### 9.2 核心表与索引

| 表 | 核心字段 | 关键约束/索引 |
|---|---|---|

| family | id、timezone | — |

| child_profile | id、family_id、nickname、grade、status | `(family_id,status)` |

### 9.3 奖励事务

单项任务提交只推进任务状态与今日进度，不直接发放星星。今日礼包领取在同一本地事务完成：

1. 锁定 `daily_reward_claim` 并验证家庭时区下的业务日期。
2. 检查全部必做任务均为 `confirmed`，选做任务不参与阻塞。
3. 检查 `(child_id,local_date)` 唯一领取约束和客户端幂等键。
4. 追加一条 `reward_ledger`，原因固定为 `daily_package`。
5. 更新 `reward_balance` 并将礼包状态改为 `claimed`。
6. 提交事务后返回唯一结算结果；重复请求查询原记录并返回相同结果。

唯一约束是最后防线，不能只使用 Redis 锁。数据库冲突时查询已有账本并返回原结果。

### 9.4 宠物互动事务

消耗星星和增加宠物属性必须在同一事务中完成。使用条件更新保证 `balance >= cost`，避免先读后写造成负数；宠物属性使用版本号或数据库条件更新处理并发。

## 10. 内容生产与每日换新

内容状态：`draft → pending_review → approved → published → withdrawn`。

发布流程：

1. 编辑内容并填写学段、知识点、难度、答案、解析和权利信息。
2. 自动校验结构、敏感词、拼音格式、答案完整性和资源可访问性。
3. 人工教研/安全审核。
4. 生成不可变 `content_release` 和资源 manifest。
5. 客户端下载 manifest 后按 hash 增量更新。
6. 紧急下架发布撤回清单；客户端联网时立即禁用，离线包设置最大有效期。

每日内容不是在线即时 AI 生成。系统从已发布内容中按年级、学习顺序、掌握状态、近期去重和数量规则确定，并保存 `content_item_id + version`，保证复盘可重复。

数学参数题允许基于审核模板和确定性种子生成；生成后服务端验证范围、唯一答案和解题步骤，再下发客户端。

## 11. 语音评测适配层

接口输入：任务类型、目标文本/拼音、语言、音频对象 ID、年龄段和请求幂等键。输出：供应商、置信度、分项结果、可解释提示、原始结果引用和审核状态。

安全规则：

- 供应商密钥只在服务端。
- 发送前确认监护同意及供应商数据处理条款。
- 音频 URL 使用分钟级临时签名，不提供永久公开地址。
- 原始音频与供应商结果设置独立保存期限。
- 低置信度不自动判错；供应商故障不阻塞其他学习流程。

Python 只可作为将来的独立算法适配服务，不承担账号、奖励和儿童数据的核心事实存储。

## 12. 身份、安全与隐私

### 12.1 身份模型

- 只有监护人拥有登录账号；孩子通过已授权设备选择档案，不建立手机号或社交账号。
- Access Token 短时有效；Refresh Token 每次使用后旋转，并通过经审查的安全存储插件保存，禁止普通 storage 明文持久化。
- 设备丢失后家长可远程撤销会话。
- 后台账号与家庭账号使用不同 issuer/audience 和权限域。

### 12.2 权限校验

任何孩子资源请求按顺序校验：令牌主体 → 家庭成员关系 → 孩子归属 → 操作角色 → 资源状态。禁止接受客户端 `childId` 后直接查询。

### 12.3 数据保护

- TLS 传输；数据库、备份和对象存储启用静态加密。
- 日志脱敏手机号、令牌、昵称、答案正文、音频和图片路径。
- 对象存储 bucket 私有，下载使用短时签名 URL。
- 密钥进入密钥管理或环境注入，不写配置库。
- 导出与删除必须通过家长门、重新认证和审计。
- 分析事件不含自由文本、录音、图片、精确位置或广告标识。

## 13. 缓存、任务与扩展

### 13.1 MVP 不强制 Redis

单实例阶段使用 PostgreSQL 完成幂等、会话撤销、调度锁和奖励一致性。出现以下需求再启用 Redis：

- 多实例验证码和短时会话
- 高频内容 manifest 缓存
- 分布式限流
- 明确测得的热点查询

Redis 不是数据库事实源，缓存失效不能导致奖励重复或权限绕过。

### 13.2 后台任务

Spring Scheduler 首版处理：每日任务预生成、月报生成、过期媒体清理和删除冻结期执行。任务使用数据库租约保证单次执行，并可人工重跑。Spring Boot 提供调度和有界任务执行配置，但仍需显式配置队列、超时和拒绝策略：[Spring 任务执行与调度](https://docs.spring.io/spring-boot/reference/features/task-execution-and-scheduling.html)。

只有出现长时语音/视频处理或明显峰值积压时，才引入消息队列和 outbox。

## 14. 部署与环境

环境：`local/test/staging/production`，测试与生产绝不共享账号、数据库、bucket 或密钥。

MVP 生产拓扑：

- 2 个 API 容器（达到正式用户量后启用）
- 托管 PostgreSQL 主实例与自动备份
- 私有对象存储 + CDN 公共内容域；儿童证明不走公共 CDN
- Nginx/云负载均衡
- 可选 Redis
- 日志、指标、错误追踪和告警

发布步骤：数据库向后兼容迁移 → API 滚动发布 → 后台发布 → 内容 release → 移动端灰度。回滚只能回应用版本，数据库使用向前修复，禁止生产环境自动 `drop` 或回滚破坏性迁移。

## 15. 可观测性与备份

关键指标：

- API P50/P95/P99、5xx、超时、数据库连接池
- 提交成功率、重复幂等命中、奖励冲突、负余额拦截
- 离线同步积压与失败原因
- 内容包下载失败、hash 校验失败、紧急下架生效延迟
- 语音供应商成功率、耗时和低置信度比例
- 删除/导出任务积压

日志使用 `traceId`，但不得把儿童数据作为标签。PostgreSQL 做自动备份与恢复演练；对象存储启用版本或生命周期策略。至少每季度实际恢复到隔离环境验证，而不是只检查“备份成功”。

## 19. 对抗性审查与已采取措施

### 恶意用户

- 重放提交刷星星：数据库幂等键、唯一账本和本地事务。
- 篡改本地余额：服务端余额为事实源，本地仅快照。
- 伪造孩子 ID：逐请求验证监护关系和资源归属。
- 枚举证明文件：私有 bucket、随机 key、短时签名 URL。
- 修改系统时间：任务日期和奖励窗口由服务端家庭时区判断。

### 挑剔评审

- 技术过度：模块化单体、Redis/队列按需启用。
- 选型偏见：未复用当前 IM/Vue 项目代码；根据实施者的 uni-app/Vue 能力、功能边界和专项风险比较五种移动端与四种后端方案。
- 内容不可复盘：每日选择和参数题固定内容版本及种子。
- AI 风险：AI 不直接向儿童发布内容。
- 素材风险：每个资源带许可证、hash 与版本。

### 极端环境

- 360px 手机固定侧栏挤压：64px 图标轨、顶部二级标签，并列入 Golden/真机测试；若仍不可读，需要产品确认是否允许手机改为底部导航。
- 弱网跨日：本地草稿、操作时间与服务端接收时间同时记录，由固定规则归属日期。
- 录音被电话中断：保存可恢复状态，释放音频会话，不自动判失败。
- 内容紧急下架但设备离线：离线包有限期、联网撤回清单和安全内容兜底。
- 动画资源损坏：hash 校验、旧版本保留和静态图降级。
